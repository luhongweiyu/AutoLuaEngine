**方法名称：** 声明 C 类型/符号并取得 C 库命名空间。

**语法：** `ffi.cdef(declarations)`、`ffi.C.symbol`、`ffi.load(nameOrPath[, global])`

**参数说明：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `declarations` | `string` | 最小化的 C 声明片段，可包含 `typedef`、结构体、枚举、函数原型和函数指针。 |
| `nameOrPath` | `string` | 库名、soname 或 Android 动态链接器允许访问的路径。`"c"` 对应 `libc.so`。 |
| `global` | `boolean`（可选） | 为真时按全局符号可见方式加载；默认是局部加载。仅在依赖库确有此要求时使用。 |
| `symbol` | `string` | 已在 `cdef` 中声明的全局变量或函数名。 |

| 返回值 | 说明 |
|---|---|
| 无 | `ffi.cdef` 成功时不返回值；声明错误会抛出 Lua 错误。 |
| `userdata` | `ffi.load` 返回库命名空间，字段访问会按声明解析符号。 |
| `cdata` | `ffi.C.symbol` 或 `library.symbol` 返回声明对应的 C 数据或可调用函数。 |

**详细说明：**

`ffi.cdef` 只登记类型和函数签名，不会把 C 代码编译进 APK。不要把带有 `#include`、宏、条件编译或
平台专用编译器扩展的整份头文件直接传入；请保留实际要用到的声明，并自行确保 `long`、`size_t`、
结构体布局等类型与目标 ABI 一致。

`ffi.C` 是当前进程的默认符号命名空间。它适合访问已全局导出的符号；在 Android 上，通常更清楚的
做法是使用 `ffi.load("c")` 或明确的库名。库名不含扩展名时会按 `lib<name>.so` 解析，例如
`ffi.load("c")` 会查找 `libc.so`。

```lua
local ffi = require("ffi")

ffi.cdef[[
    int getpid(void);
    double strtod(const char *text, char **end);
]]

local libc = ffi.load("c")
local pid = ffi.tonumber(libc.getpid())
local value = ffi.tonumber(libc.strtod("3.25", nil))
print("pid", pid, "value", value)
```

符号不存在、库不可见或声明与真实 ABI 不一致时会报错或造成原生异常。正式功能不应依赖猜测的系统
私有符号；需要稳定 Android 能力时，请等待或新增项目正式 API。
