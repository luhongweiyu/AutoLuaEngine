**方法名称：** 管理 cdata 生命周期、元类型、错误码和 Lua 回调。

**语法：** `ffi.gc(cdata, finalizer)`、`ffi.metatype(ctype, metatable)`、`ffi.errno([value])`、`ffi.cast(callbackType, function)`

**参数说明：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `cdata` | cdata | 要附加或移除 finalizer 的数据，或要转换为 callback 的函数指针。 |
| `finalizer` | `function` 或 `nil` | cdata 被 Lua GC 回收时调用；传 `nil` 可移除已设置的 finalizer。 |
| `ctype` | `string` 或 ctype | 已声明的结构体或联合体类型。一个记录类型只能注册一次元类型。 |
| `metatable` | `table` | 可定义 `__index`、`__newindex`、`__tostring`、`__gc` 等 C 数据行为。 |
| `value` | `integer`（可选） | `ffi.errno(value)` 设置当前线程的 C `errno`，并返回设置前的值。 |
| `callbackType` | `string` 或 ctype | 指向非可变参数 C 函数的指针类型。 |

| 返回值 | 说明 |
|---|---|
| `cdata` | `ffi.gc` 返回原 cdata；`ffi.cast` 返回可调用函数指针或 callback。 |
| ctype | `ffi.metatype` 返回已注册元类型的 ctype。 |
| `integer` | `ffi.errno()` 返回当前线程的 C 错误码；设置时返回旧值。 |
| 无 | `callback:free()` 和 `callback:set(function)` 成功时不返回值。 |

**详细说明：**

`ffi.gc` 适合为已分配的原生资源绑定释放函数，但 GC 时机不可预测；需要立即释放的资源应优先使用
明确的 C 释放函数。`ffi.metatype` 适合为结构体添加 Lua 侧访问行为，注册后不能再次替换同一类型的
元类型。

回调由 `ffi.cast` 创建。只要 C 侧还可能调用回调，Lua 侧必须保留该 callback 的强引用；确认 C 侧
不再保存该函数指针后再调用 `:free()`。C 侧若从其他线程调用 Lua callback，会破坏 Lua VM 的线程
安全，属于不支持的用法。

可变参数函数也可以调用，但尾随参数没有固定原型。为避免 32/64 位与浮点提升规则造成歧义，应为
尾随参数显式创建准确的 cdata，例如 `ffi.new("int", 42)` 或 `ffi.new("double", 3.5)`。

```lua
local ffi = require("ffi")

ffi.cdef[[
    typedef struct {
        int value;
    } xiaoyv_counter;
]]

ffi.metatype("xiaoyv_counter", {
    __tostring = function(counter)
        return "counter=" .. ffi.tonumber(counter.value)
    end,
})

local callback = ffi.cast("int (*)(int)", function(value)
    return value + 1
end)

assert(ffi.tonumber(callback(41)) == 42)
callback:set(function(value) return value + 2 end)
assert(ffi.tonumber(callback(40)) == 42)
callback:free()
```

`ffi.errno()` 仅反映当前线程最近的 C 错误码；在调用后立即读取，且不要把它与 Java 异常、项目 API
返回的 `nil, errorMessage` 混为同一套错误机制。
