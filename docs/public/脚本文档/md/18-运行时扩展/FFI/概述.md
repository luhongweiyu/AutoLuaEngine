# FFI

> **状态：已完成。** 已完成真实运行时验证，包括结构体、浮点、可变参数、Lua 回调和外部
> C/C++ SO 加载。错误的声明、指针、库或线程使用仍可能直接使脚本进程崩溃；普通 Android
> 自动化能力仍应优先使用项目正式 API。

FFI 用于受控的原生扩展开发。以下三种入口是同一个模块表：

```lua
local a = m.ffi
local b = ffi
local c = require("ffi")
assert(a == b and b == c)
```

`require("cffi")` 不是公开入口，也不应写入脚本依赖。

| 能力 | 可用范围 |
|---|---|
| C 声明与库加载 | 函数原型、`typedef`、结构体、联合体、枚举、数组和函数指针声明；加载 Android 动态链接器可见的库。 |
| C 数据 | `ffi.new`、`ffi.cast`、ctype、cdata、结构体字段、数组索引、字符串和内存复制。 |
| C 调用 | 整数、浮点、指针、结构体/数组数据、可变参数和 Lua 回调。实际 ABI 仍取决于设备 CPU 架构。 |
| 类型与资源 | 大小/对齐信息、元类型、垃圾回收回调、`errno` 与显式回调释放。 |

## 使用边界

- `ffi.cdef` 只解析 C 声明，不会编译 C 代码，也不会处理 `#include`、宏展开或完整系统头文件。将
  所需的类型和函数原型整理成最小声明片段。
- `ffi.load("c")` 会按 Android 命名规则加载 `libc.so`。用户扩展应先通过
  `LuaEngine.getExtensionPath(relativePath)` 取得扩展页已导入的私有路径；受 Android linker
  namespace 限制，不能把任意系统路径或桌面平台库当作可加载目标。
- 多个 SO 存在依赖时，脚本按实际依赖顺序加载。需要被后续库解析的依赖使用
  `ffi.load(dependencyPath, true)`；第二个参数使该库以全局可见方式加载。
- FFI 运行在本次一次性脚本 Worker 中。Root 模式的 Worker 为 uid=0，非 Root 模式的 Worker
  保持 App UID；两种模式使用同一套 FFI 实现。固定截图、输入和系统控制能力仍优先使用项目 API，
  由平台按当前模式路由。
- FFI 不会校验指针地址、缓冲区长度和声明是否与真实 C 函数一致。传错类型、把 32/64 位大小写错
  或在库已卸载后继续使用函数，都可能造成原生崩溃。
- Lua 回调只能由运行该 Lua VM 的同一线程调用；外部原生线程不得直接回调脚本。回调交给 C 侧后，
  要一直保留 Lua 引用，并在 C 侧不再调用后显式 `callback:free()`。
- 这是基于 CFFI 的实现，不承诺与 LuaJIT FFI 的每一项边缘语义完全相同。位域、C++ 类、预处理后
  的复杂头文件，以及结构体或联合体按值跨 ABI 传递，都应先在目标 ABI 上单独验证。
