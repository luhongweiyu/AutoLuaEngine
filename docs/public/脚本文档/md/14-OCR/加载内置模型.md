**方法名称：** 加载内置 OCR 模型。

**语法：** `m.ocr.loadBuiltin([name[, threads]])`

**参数说明：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | `string?` | 否 | 脚本使用的模型名称，默认 `builtin`。 |
| `threads` | `integer?` | 否 | ONNX 推理线程数，默认 `2`，范围 `1` 到 `32`。 |

| 返回值 | 说明 |
|---|---|
| `boolean` | 成功加载或复用已有模型时返回 `true`。 |
| `nil, string` | 预设文件未导入、ONNX session 创建或参数校验失败时返回错误信息。 |

**详细说明：**

```lua
assert(m.ocr.loadBuiltin())

local imagePath = "/sdcard/xiaoyv/scripts/current.png"
assert(capture(imagePath))

local result, errorMessage = m.ocr.read("builtin", imagePath, {
    useAngle = true,
})
if not result then
    print("OCR 失败：", errorMessage)
end

m.ocr.release("builtin")
```

`loadBuiltin` 使用一组固定名称的 PP-OCRv4 mobile 中文/英文检测、识别、方向分类模型和匹配字典。
它们不在基础 APK 内：先将目标 CPU ABI 对应的 `libonnxruntime.so`、
`ch_PP-OCRv4_det_mobile.onnx`、`ch_PP-OCRv4_rec_mobile.onnx`、
`ch_ppocr_mobile_v2.0_cls_mobile.onnx`、`ppocr_keys_v1.txt` 放入
`/sdcard/xiaoyv/extensions/`，然后在 App 的“扩展”页逐个点击“导入”。导入不会加载代码；本方法
实际创建 ONNX session 时才按需加载运行时和模型。设置 `useAngle = true` 时使用方向分类模型。

文件名、CPU ABI、依赖和内容由脚本作者自行负责。错误的文件不会在导入时被拦截，加载失败时会以
`nil, string` 返回底层错误。

模型名称遵循与 `m.ocr.load()` 相同的管理规则：同名、相同线程数重复加载直接复用，不增加引用
次数；同名已加载其他配置时返回错误，需先 `release(name)`。`release` 释放 session 内存，不删除
已导入的文件；如需替换模型或字典，在共享扩展目录替换后重新点击“导入”，并先 `release(name)`
再重新加载。只有替换已经成功加载的 native 运行时 SO 时才需要重启脚本引擎进程。
