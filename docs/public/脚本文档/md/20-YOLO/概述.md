`m.yolo` 使用可选的 NCNN CPU 运行时加载兼容的 YOLOv5 模型，并检测当前屏幕或普通图片文件。
基础 APK 不携带 `libxiaoyv_yolo.so` 或模型。先把当前 APK CPU ABI 对应的运行库放到：

```text
/sdcard/xiaoyv/extensions/yolo/libxiaoyv_yolo.so
```

然后在 App“扩展”页导入整个 `yolo` 目录。导入只复制文件，不执行 native 代码，也不校验 ABI、
依赖或内容；`m.yolo.isAvailable()` 为 `true` 只表示文件已经导入，首次 `load/init` 才真正加载。

模型由标签、NCNN param 和 bin 三个普通文件组成。绝对路径直接使用；相对路径基于当前脚本工作
目录解析，不支持把模型放在 ALPKG 中。当前后端固定为标准 YOLOv5 的三个检测头、stride
`8/16/32` 和对应 anchors，不代表任意 YOLO 或任意 NCNN 模型都能直接使用。

最简流程：

```lua
local ok, errorMessage = m.yolo.init(
    "models/coco.txt",
    "models/yolov5s.param",
    "models/yolov5s.bin"
)
assert(ok, errorMessage)

local items, detectError = m.yolo.detect()
assert(items, detectError)
for _, item in ipairs(items) do
    print(item.label, item.prob, item.x, item.y, item.w, item.h)
end

m.yolo.release()
```

`init/detect/release` 固定使用名称 `default`，方便单模型脚本；多模型脚本使用
`load/detectScreen/detectFile/release` 并显式传名称。检测成功返回 Lua 数组，每项包含
`x/y/w/h:number`、`label:string`、`prob:number`；没有命中时返回空数组，失败返回
`nil, errorMessage`。

当前只支持 CPU。`useGpu` 是加载模型时的配置，设为 `true` 会明确失败；单次检测不能切换 GPU。
本模块不提供 Java `Bitmap` 或全局 `YoloV5` 兼容入口。
