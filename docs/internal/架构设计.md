# 架构设计

## 当前分层

```text
App/UI
  负责脚本选择、状态展示、设置、控制悬浮窗、音量键控制、原生脚本 UI 和 RootDaemon 生命周期

RootDaemon（uid=0）
  负责 Root 截图、输入注入、输入法系统切换、物理音量键和一次性 Root Worker 监督；
  不加载脚本、libengine.so、模型或用户 SO

控制进程 (:engine)
  EngineService / EngineHttpServer / EngineWorkerCoordinator 负责运行会话、状态、HTTP、
  日志接续、ImGui Surface 和 Root/本地 Worker 启停，本身不加载 libengine.so

一次性脚本 Worker
  Root 模式为 RootDaemon 启动的 uid=0 EngineWorkerMain，非 Root 模式为 App UID 的
  LocalEngineWorkerService :worker；二者共用 EngineWorkerEndpoint、NativeEngine、
  libengine.so、语言运行时、JavaInterop、FFI、扩展和 Dear ImGui 渲染

IDE 工具链
  VSCode 插件与 Qt 工具平级直连 EngineHttpServer；前者负责脚本开发，后者负责抓图、
  取色、图像分析和投影
```

## IDE 工具边界

`ide/xiaoyv-tools` 是 IDE 工具链中的 Windows 桌面工具，不属于 Windows、Android 或 iOS
脚本引擎的平台实现。桌面系统只是它当前的运行环境。

```text
ide/vscode-extension
  脚本运行、暂停、继续、停止、日志、打包，以及启动独立抓图工具

ide/xiaoyv-tools
  Qt 多标签图片工作区、取色、二值化、点阵字库、设备截图和投影

shared/native/image_core
  不依赖 Qt/Android 的颜色规则、二值化、点阵生成和完整点阵匹配
```

VSCode 与 `xiaoyv_tools.exe` 不互相中转。ADB 模式下二者分别管理自己的 forward，Qt 工具
使用动态本机端口；LAN 模式下分别连接设备 IP。Android `EngineHttpServer` 使用并发客户端
处理器，允许二者同时工作。

工具截图直接读取 `screen_api` 当前 RGBA8888 帧。投影只通过 `PUT /tool/image` 上传图片，
再调用 `viewer.openImage(fileId)` 启动主进程全屏 Activity。投影不进入脚本 API，也不在
`libengine.so` 建立额外显示状态。详细设计见
[IDE 抓图取色工具](ide/PC_抓图取色工具.md)。

## Native 与语言绑定边界

`libengine.so/core/api` 保存语言无关的真实能力；`system_c_api` 与各子函数表只提供稳定
C ABI，不承载业务实现。Lua 的参数转换、对象包装、回调和多线程语义位于
`libengine.so/runtime/lua`，运行时 Lua 模块位于 Android assets，并通过
`package.preload + require` 独立加载。

固定能力由 Lua HostApi 调用统一 C ABI。动态 Java 对象不能预先展开成固定函数表，统一经
Lua Java Bridge、JNI 和 `JavaInteropBridge` 完成反射与回调。兼容层的 Android 扩展能力通过
受控 `platformCall -> engine_deviceCallJson` 路由；未知操作必须失败，不能成为任意 JNI 入口。

本架构文档不维护源码文件和导出函数全清单。当前 C ABI、函数表版本及 Lua 映射以
[统一 API 契约](contracts/API_契约.md)为准；加载顺序、二进制编码、坐标缩放和平台排除项见
[Android Lua 兼容层](platform/android/ANDROID_Lua_兼容层.md)。Lua 多线程属于语言运行时语义，
后续 JS 和 Go 使用各自的并发模型，不复用 Lua 线程对象。

## 当前边界规则

- App/UI 只负责界面、脚本文件选择、悬浮窗、无障碍对象和状态展示。
- 音量键是 App 控制入口：Root 模式由 RootDaemon 直接读取 evdev，非 Root 模式由无障碍服务
  接收；两条路线最终都只向 `EngineService` 发送运行或停止 Intent。
- `:engine` 只负责 HTTP、脚本会话控制、Worker Binder、日志接续和状态广播；不执行脚本。
- `ScriptImGuiService` 位于 `:engine`，只负责透明 Surface、触摸和输入法转发；控件状态、
  事件队列及绘制命令位于本次 Worker 的 `libengine.so`。
- 所有语言无关设备 API 的真实逻辑先进入 `libengine.so/core/api`，语言绑定层只做转换。
- Lua 多线程和动态 Java 对象属于语言运行时能力，实现在 `libengine.so/runtime/lua`。
- `system_c_api` 是 C ABI 门面，不承载具体业务逻辑。
- Java 桥只处理 Android 必须由 Java 完成的能力，例如 RootDaemon、Worker 启动外壳、
  App UID 组件宿主和平台桥接。
- RootDaemon 与 `:engine` 都不加载用户 SO。脚本结束或强停只退出 Worker，不关闭 RootDaemon，
  下一次 Root 运行也不会重新请求 `su`。
- Root/非 Root 只改变 Worker UID 和启动方式；API、C ABI 和语言绑定不分叉。非 Root 下的
  Root 类调用按底层实际结果返回，不在控制层伪造错误、重试或走备用路线。

## 点阵字库路径

```text
Lua / JS / Go / 插件
  -> engine_font* C ABI
  -> core/api/font_api
  -> screen_api 当前截图缓存
```

字库以 `shared_ptr` 不可变快照保存，识字线程取得快照后不持有字库表锁。设置或追加字库时先
构建新快照，再替换指定索引；追加同一索引的写操作串行执行，避免并发追加丢数据。

每个字形保存任意宽高的完整点阵，按行压缩成 `uint64_t`。加载时从完整点阵中选取纵向 11 位
低碰撞特征；识字区域也建立 `0` 到 `2047` 的坐标桶。特征只负责缩小候选范围，最终匹配始终
比较完整点阵中的缺失点和多余点。`fontFindStr` 使用完整识字结果，`fontFindStrFast` 只搜索
目标标签索引，两者共用同一套最终点阵比较。

## 脚本 UI 路径

```text
Lua HostApi
  -> system_c_api / core/api/ui_api
  -> AndroidBridge JNI（本次 Worker）
  -> EngineWorkerBridgeProvider（App UID 宿主桥）
  -> App 主进程的 Dialog Overlay Service、HUD Service、WebView Activity
  -> EngineHttpServer 的 ui.event
  -> IEngineWorker
  -> core/api/ui_api 会话队列
  -> Lua m.ui.waitEvent / m.hud.waitEvent / m.web.waitEvent
```

`libengine.so` 负责会话 ID、配置、事件队列、等待和 C ABI；App 主进程只负责 Android
View、窗口和 WebView。三个界面实现分别是：

- `ScriptDialogOverlayService`：WindowManager 原生提示、确认、输入、选择和表单；框外触摸穿透。
- `ScriptHudService`：脚本 HUD 悬浮层、按钮、拖动和定时关闭。
- `ScriptWebActivity`：HTML、WebView 和 JavaScript bridge。

脚本 UI 事件不会在 Android UI 线程执行 Lua。事件先通过本机 HTTP `ui.event` 写入
native 队列，再由脚本线程读取。完整 API 见 [脚本文档（界面）](../public/脚本文档.md) 与
[Android 脚本 UI（实现）](platform/android/ANDROID_脚本_UI.md)。

## ImGui 路径

```text
Lua imgui.* / 后续 JS、Go / 插件 SO
  -> runtime/lua/imgui_lua_api 或 EngineImGuiApi
  -> core/imgui_c_api
  -> core/api/imgui_api 控件模型与事件队列
  -> Worker 内 platform/imgui_renderer（Dear ImGui + EGL/OpenGL ES 3）
  <-> IEngineWorker Binder
  <-> :engine/ScriptImGuiService（透明 Surface、触摸、键盘和输入法）
```

Dear ImGui `v1.92.8`、渲染器和全部通用能力编入现有 `libengine.so`，不增加业务 SO。
渲染线程独占 EGL、OpenGL ES 和 Dear ImGui context；它只读取不可变渲染快照并把交互结果
写入事件队列，不能直接执行 Lua。Lua 事件泵取得 VM Gate 后才执行回调，因此回调可以再次
调用 `imgui.*`。

App 主进程的控制悬浮窗与 ImGui 无关，不会随脚本 ImGui 关闭。脚本结束、停止、强停或
`imgui.close()` 会统一移除 `:engine` 的 ImGui Surface；Worker 退出再由内核回收渲染线程、
EGL、纹理、句柄和语言回调。完整契约见 [Android ImGui](platform/android/ANDROID_ImGui.md)。
