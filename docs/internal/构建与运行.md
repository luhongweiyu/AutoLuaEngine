# 构建与运行

## 构建环境

测试环境：雷电 `x86_64` 模拟器。日常测试只编译 x64 Debug；正式发布和双 ABI 验收编译
`arm64-v8a`、`x86_64`。

Gradle 命令在 `engines/android` 执行，可选运行时脚本在仓库根目录执行。必须使用 Android Studio
自带的 JDK 17（或等价 JDK 17）；APK 最低支持 Android 7（API 24）。

Root Worker 验收使用 x64 Debug。

## 编译命令

### 雷电 x64 测试

在 `engines/android` 执行。按需选择安装或只生成 APK：

```powershell
.\gradlew.bat -PxiaoyvEnableX64Debug=true :app:installX64Debug
.\gradlew.bat -PxiaoyvEnableX64Debug=true :app:assembleX64Debug
```

在仓库根目录执行可选运行时命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/build_android_yolo.ps1 -Abi x86_64
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/prepare_android_optional_runtimes.ps1 -Abi x86_64
```

### 正式发布 / 双 ABI 验收

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/build_android_yolo.ps1 -Abi arm64-v8a,x86_64
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/prepare_android_optional_runtimes.ps1 -Abi arm64-v8a,x86_64
.\gradlew.bat :app:assembleArm64Release :app:assembleX64Release
```

仅在 ABI、CMake/Gradle 配置变更，native 旧产物异常或需要清理构建目录时使用：

```powershell
.\gradlew.bat clean -PxiaoyvEnableX64Debug=true :app:installX64Debug
```

新增 ABI 前补齐构建、依赖和运行时验收。

> Gradle 不要在 UNC/SMB 共享路径下执行；使用本地磁盘工作副本。

## 项目固定签名

Android 的 `debug` 与 `release` 构建使用项目固定签名：

```text
engines/android/signing.properties
engines/android/signing/xiaoyv-project.keystore
```

缺失配置或 keystore 时构建会失败。正式发布若更换签名，需同步更新构建配置并完成覆盖安装验证。

## 调试 APK 覆盖安装

覆盖安装：

```powershell
adb -s <设备序列号> install -r <APK 路径>
```

签名或版本不匹配时不要改用卸载、降级安装或清理数据。

## 可选 YOLO 运行时

YOLO 的 NCNN 推理后端是独立的 `libxiaoyv_yolo.so`。

脚本将产物放在 `engines/android/optional-libs/yolo/<abi>/libxiaoyv_yolo.so`，源码未变时自动复用。
基础 APK **从不**打包该库，APK 构建不需要额外 Gradle 参数。将需要的产物以它本身要求的文件名复制到设备：

```powershell
adb -s <设备序列号> shell mkdir -p /sdcard/xiaoyv/extensions/yolo
adb -s <设备序列号> push `
  engines/android/optional-libs/yolo/<abi>/libxiaoyv_yolo.so `
  /sdcard/xiaoyv/extensions/yolo/libxiaoyv_yolo.so
```

随后在 App 的“扩展”页导入 `yolo` 目录。导入只复制为 App 私有只读副本，不执行 native
代码；Worker 中的 C ABI、`m.yolo` 或插件第一次实际加载、检测 YOLO 模型时才尝试加载它。App
不检查签名、SHA-256、版本、ABI、文件名或依赖，错误由用户自行处理。模型的 `labels`、
`param`、`bin` 是普通文件路径，不属于 ALPKG；Lua 用法见公开 [YOLO 概述](../public/脚本文档/md/20-YOLO/概述.md)，
JS、Go 绑定仍属于后续。

## 可选 OpenCV 与 RapidOCR 运行时

OpenCV 和 RapidOCR 的 Java 类仍在基础 APK 中，大体积 native 库从锁定版本的 Gradle AAR 提取。

该脚本不重新编译 OpenCV 或 ONNX Runtime，只把 Gradle 已下载的 AAR 中的文件取到：

```text
engines/android/optional-libs/opencv/<abi>/libc++_shared.so
engines/android/optional-libs/opencv/<abi>/libopencv_java4.so
engines/android/optional-libs/rapidocr/<abi>/libonnxruntime.so
```

OpenCV 使用前，将前两份文件放入 `/sdcard/xiaoyv/extensions/opencv/` 并在 App 扩展页导入 `opencv` 目录。脚本的
`findCircle`、`cv.snapShot` 或 `import("org.opencv.*")` 首次实际使用 OpenCV 时才按顺序加载它们。

RapidOCR 使用前，将 `libonnxruntime.so` 和下列预设模型文件一并放入
`/sdcard/xiaoyv/extensions/rapidocr/`，然后导入 `rapidocr` 目录：

```text
engines/android/optional-resources/rapidocr/ppocr_v4_mobile/ch_PP-OCRv4_det_mobile.onnx
engines/android/optional-resources/rapidocr/ppocr_v4_mobile/ch_PP-OCRv4_rec_mobile.onnx
engines/android/optional-resources/rapidocr/ppocr_v4_mobile/ch_ppocr_mobile_v2.0_cls_mobile.onnx
engines/android/optional-resources/rapidocr/ppocr_v4_mobile/ppocr_keys_v1.txt
```

ONNX Runtime 官方 Java 绑定所需的 `libonnxruntime4j_jni.so` 体积很小，仍留在基础 APK；它在脚本
实际加载 OCR 模型时连接已导入的 `rapidocr/libonnxruntime.so`。导入流程不校验文件名、内容、ABI 或依赖；
上述名称只是内置能力实际请求的名称，错误组合由加载器直接报告。

## 脚本目录

Android 脚本默认存放在：

```text
/sdcard/xiaoyv/scripts/
```

首次启动会申请脚本存储访问：Android 11 及以上打开“所有文件访问”系统页，Android 10
及以下申请传统读写存储权限。授权后创建默认目录，并且只在当前安装首次初始化时复制内置
示例，不覆盖已有文件，用户之后删除示例不会再次生成。用户可在 App 设置页直接输入
`/sdcard` 下的其他脚本目录。脚本列表、悬浮窗运行入口和引擎读取的都是当前配置目录中的
真实文件，外部编辑器保存后返回 App 即可刷新。

## 加密脚本包

脚本项目根目录使用 `alpkg.json` 指定入口，`entry` 必填，`exclude` 可选：

```json
{
  "entry": "main.lua",
  "exclude": [".git/", ".vscode/", "dist/", "*.bak"]
}
```

首次打包时若缺少 `alpkg.json`，打包器会自动创建这份默认配置后继续执行；若项目中没有
`main.lua`，会在入口校验阶段明确报错。

执行 `tools/pack/构建打包器.ps1 -Release` 后，可使用：

```powershell
.\tools\pack\打包脚本包.ps1 -ProjectDirectory 'E:\我的脚本项目'
```

输出为 `项目目录\dist\项目名.alpkg`。App 会在脚本列表显示并可直接运行 `.alpkg`：Lua
文件是去调试信息的 Lua 5.4.8 字节码，经 XChaCha20-Poly1305 认证加密后由 `libengine.so`
从 ZIP 内存加载；HTML、图片和其他资源保持原格式，直接从包内读取，不解压到磁盘。
包内 HTML 的相对 CSS、JavaScript、图片等资源会自动从同一个 `.alpkg` 读取。
脚本需要读取 JSON、CSS、图片等原始资源时，可调用
`m.read_alpkg_file("项目相对路径")`；它只读取已打包资源，不回退到包外文件。
完整格式见 [ALPKG 格式](../../shared/package/ALPKG_格式.md)。

## 当前运行范围

当前运行范围包括 App/UI、EngineService、HTTP 通讯、脚本运行与停止、日志、Root 设备能力、
截图与输入、找色找图、OCR、点阵字库、脚本 UI、ImGui、Java 互操作、Lua 子线程和 ALPKG
资源读取。

完整参数、返回值和兼容命名空间说明见 [脚本文档](../public/脚本文档.md)；C ABI 与实现边界见
[统一 API 契约](contracts/API_契约.md)。这里不再复制容易过期的函数清单。
