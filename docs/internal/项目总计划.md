# 小鱼精灵项目总计划

## 当前目标

第一阶段只做 Android + Lua。固定脚本 API 的真实逻辑收敛到
`libengine.so/core/api`，动态 Java 对象能力由 `libengine.so/runtime/lua` 接入。

当前已形成以下主体范围：

- Android App、常驻 `:engine` 控制进程、RootDaemon，以及 Root/App UID 两种外壳共用的
  一次性脚本 Worker。
- HTTP 会话控制、脚本运行与停止、状态、日志接续、原生脚本 UI 和 ImGui Surface 协作。
- `libengine.so/core/api` 中的语言无关能力，以及面向语言绑定和插件的稳定 C ABI；能力覆盖
  运行时、截图与图色、OCR、点阵字库、输入与输入法、设备、脚本 UI、包资源和可选扩展。
- Lua 5.4 运行时、Lua-Java 动态互操作、native 多线程、FFI、网络、OpenCV、文件与无障碍
  兼容层；运行时模块通过 `package.preload + require` 独立加载。
- ALPKG 加密脚本包、包内模块与资源，以及 VSCode 插件和独立 Qt 抓图取色工具。
- Android 与 PC 共用的颜色规则、二值化、点阵生成和完整点阵匹配核心。

固定 API 走 `core/api -> system_c_api -> Lua HostApi`；Java 动态调用走
`Lua Java Bridge -> JNI -> JavaInteropBridge`。未完成或实验能力可以保留内部 C ABI、扩展开发
资料和带状态的公开说明，但不能描述成脚本已经可直接依赖的稳定能力。

Android 运行时中，`libengine.so`、语言 VM、JavaInterop、FFI 和扩展只进入本次一次性
Worker；Root 模式 Worker 为 uid=0，非 Root 模式 Worker 为 App UID。App 主进程、`:engine`
控制进程与 RootDaemon 均不加载用户 SO。完整边界见
[Android 引擎进程拆分](platform/android/ANDROID_引擎进程拆分.md)。

## 阶段与里程碑

- 基础架构里程碑：常驻控制端、一次性 Worker、Root/App UID 两种外壳、Lua 5.4、统一 C ABI、
  脚本 UI、ImGui、ALPKG 和 IDE 控制链已经形成，后续功能沿现有分层继续闭环。
- 第一版里程碑（当前阶段）：产品实现与发布边界固定为 Android + Lua，APK、插件、FFI 和
  可选 native 扩展固定为 `arm64-v8a`、`x86_64`；公开文档必须区分可直接依赖、实验和未完成状态。
- 语言扩展里程碑（后续）：在同一 `core/api` 与 C ABI 上接入 JavaScript、Go，各自保留自然的
  对象包装和并发模型，不复制 Android 业务逻辑。
- 平台扩展里程碑（后续）：PC、iOS 脚本引擎复用语言无关契约和共享算法，但平台宿主、权限与
  系统桥接按各自实现，不把 Android 内部协议当成跨平台契约。

## 能力范围的权威入口

本计划不再手抄 C ABI、Lua 函数或源码文件清单，避免同一能力在多处维护后漂移：

- 已实现的分层、C ABI、函数表版本与 Lua 映射以
  [统一 API 契约](contracts/API_契约.md)为准。
- 用户可依赖的 Lua 接口以[公开脚本文档](../public/脚本文档.md)及其 `catalog.json` 为准。
- Android 平台路由、线程和生命周期细节按任务阅读
  [Android 平台文档索引](platform/android/README.md)中的对应实现说明。

## 当前未完成边界

- 第一版实际运行时只有 Android + Lua；JavaScript、Go 及 PC/iOS 脚本引擎属于后续阶段。
- YOLO 的 `core/api`、`EngineYoloApi` / C ABI、可选运行时、目录导入链路和 Lua `m.yolo`
  已接入；JS、Go 绑定属于后续。x86_64 已用一组临时外部模型完成整图真实推理验收，但仓库
  不随附正式模型，区域坐标仍未做独立设备验收；该模型来源未明确声明权重许可，不得提交、打包
  或分发。
- `getOaid` 的 Lua、C ABI 和 Android 路由调用链保留，但 Android 端尚未接入 MSA 或 OEM OAID
  provider，当前真实返回为 `nil`，不能用 `ANDROID_ID` 冒充。
- OpenCV、RapidOCR 和 YOLO 是可选目录扩展，分别按 `opencv/`、`rapidocr/`、`yolo/` 整个
  目录导入，并保留包内相对路径。

## 下一步原则

新增语言无关设备 API 时先做 `core/api` 真实现，再做 C ABI 门面，最后接 Lua / JS / Go。
语言绑定层不写最终设备逻辑。

动态对象桥是例外：Java 的任意类和方法无法预先定义固定 C ABI，统一反射、重载和
类型转换放在 `JavaInteropBridge`，各语言运行时只实现自己的对象包装与回调接入。
语言自身的并发模型也是例外：Lua 使用 native worker + VM Gate，JS 使用事件循环，
Go 使用 goroutine，三者只在调用设备 API 时汇合到 `core/api`。

每个能力一次只做一个清晰闭环：

1. `core/api` 核心实现。
2. Android/Root helper 桥接。
3. C ABI 门面。
4. Lua 绑定。
5. 文档。
6. 示例脚本。

未完成闭环的能力若进入公开资料，必须显式标注尚未完成或实验状态，并准确列出已完成层级与
缺失层级，不能提供虚构的可运行示例。

## IDE 与图像工具原则

- VSCode 和 Qt 工具是平级客户端，不互相中转。
- 每个 ADB 客户端独立管理端口转发，Qt 工具使用动态端口；局域网客户端直接连接设备。
- 图像算法优先进入 `shared/native/image_core`，Android 与 PC 不各写一套。
- 投影只保留“上传图片”和“设备打开图片”，退出由设备返回键完成。
- Qt 工具保持独立可执行，VSCode 只负责发现、构建和启动它。
