# 0011：Android 本地扩展文件导入与按需加载

- 状态：已接受（取代 0010 中“可选 native 运行时只能随 APK 打包”的分发部分）
- 日期：2026-07-30

## 背景

YOLO、OpenCV 和 RapidOCR 的 native 运行时与模型会显著增大基础 APK，但并非所有用户都会使用。
同时，小鱼精灵后续需要允许用户自己编写 native 扩展，不能只为内置功能预设分类、文件名、签名或
版本策略。

用户明确选择自行负责导入文件是否可信、是否匹配 CPU、是否满足依赖以及是否使用正确名称；应用不应
把这类本地扩展改造成受控下载市场。

## 决定

1. 用户可将任意普通文件直接放到平铺目录 `/sdcard/xiaoyv/extensions/<文件名>`。不按功能、ABI、
   后缀或来源创建子目录，也不由 App 根据文件名推断其用途。
2. App 的“扩展”页显示该目录最外层的全部普通文件。每行的“导入”只复制选中的原文件名到 App
   私有导入目录，并设为只读；不校验签名、SHA-256、App 版本、ABI、后缀、内容或依赖，也绝不在
   导入时执行 `System.load`。
3. native 文件仅在正在运行的脚本实际请求相应功能时按需加载。YOLO 当前按固定运行时文件名
   `libxiaoyv_yolo.so` 请求已导入文件；用户修改或放错名称、CPU ABI、依赖时，由 linker 的加载
   错误直接反馈。已成功加载的 SO 不能在同一引擎进程中热替换，重新导入同名文件后重启引擎进程生效。
4. 私有只读副本是 Android 动态 native 加载的运行条件，不是安全校验或文件所有权判断。共享目录中的
   原文件仍由用户自由替换；只有用户再次点击“导入”才会覆盖对应私有副本。
5. 不自动加载所有已导入文件。用户自写 native 扩展必须通过后续明确的脚本/插件加载 API 请求自己的
   文件；该公开 API 不能由本决定臆定，也不得占用现有 Java `import()` 语义。
6. 模型、字典和其他非可执行数据仍是普通文件路径，且不属于 ALPKG。各能力后续决定其模型管理 API
   时可以复用扩展目录或使用独立普通路径，但不得把模型文件伪装成脚本包资源。

## 后果

- 基础 APK 不再打包 YOLO 可选 SO；YOLO 独立编译产物可由用户按需复制、导入。
- “已导入”仅表示完成文件复制，不表示可在当前设备加载成功；运行时错误由用户处理。
- 本地功能文件无签名或完整性屏障，导入的 native 代码与 App 处于同一进程权限边界。这是用户明确
  接受的开放扩展取舍，不能在 UI 或文档中暗示 App 已验证其安全性或兼容性。
- OpenCV 已将 `libc++_shared.so` 与 `libopencv_java4.so` 拆为按需导入文件；RapidOCR 已将
  `libonnxruntime.so` 和 PP-OCRv4 mobile 模型拆为按需导入文件。两者保留原有图像与 OCR API，
  Java 绑定所需的小型代码仍在基础 APK 中。设备端端到端验收仍须覆盖各 CPU ABI。
