# 0006：Android Lua 公开层与内部实现边界

- 状态：已接受
- 日期：2026-07-29

## 背景

Android Lua 兼容能力同时经过 `m`、Lua 适配脚本、`_host`、C ABI 和 Java 平台桥接。此前部分
整理把 HostApi 的模块形状当成公开 API 的依据，导致 `m` 层出现内部便利名称，公开文档也按
“兼容来源”而非脚本作者的功能任务分类。

## 决定

1. `m` 是默认、正式的 Lua 脚本契约。函数名、参数顺序、可选参数、返回值、失败语义和用户
   文档优先选择懒人精灵或触动精灵中更清晰且可真实实现的一方；`lr`、`cd` 的历史差异不得
   反向扩展 `m` 的签名。
2. `_host`、Lua 桥接、Java、RootDaemon 与 Android 平台路由是实现细节。它们可独立命名、拆分
   或重构，不能为了与 `m` 同名而牺牲项目内部设计；反过来，`m` 也不约束内部调用结构。C ABI
   是单独文档化的扩展开发契约，不以 Lua 桥接的内部形状为依据。
3. 已经误导性导出的内部便利入口不再作为正式 API 文档化。例如 LuaSocket 使用
   `require("socket.http")`，不把 `m.http` 作为额外公共模块。
4. 本轮不扩展 `lr`、`cd` 的成员或行为；兼容映射以后按各自来源统一整理。用户文档只宣传 `m`
   的规范入口，迁移说明只解释命名空间用途，不预支尚未完成的兼容承诺。
5. 公开文档和目录按网络、输入、图像/找色、设备、运行时、无障碍和扩展开发等用户任务分类。
   C ABI 可作为面向扩展开发者的公开内容；仅未完成或实验性能力标注状态。

## 后果

- 新增 Android API 时，先写出 `m` 公开签名和文档归属，再为它实现 Lua 适配与内部桥接。
- 内部 HostApi 不再需要复刻第三方命名，减少跨层耦合。
- 现有 `m` API 调整必须同步更新 API 契约、公开函数页、API 总览、`catalog.json` 与针对性测试。
