# 0001：内部权威资料与公开发布边界

- 状态：已接受
- 日期：2026-07-27
- 更新：[0006：Android Lua 公开层与内部实现边界](<0006-Android Lua公开层与内部实现边界.md>)
  补充了公开 C ABI、扩展资料及未完成/实验能力的状态标注规则。

## 背景

原 `docs/` 同时存放项目计划、架构与实现说明、行为契约、用户 API 文档和历史核对。后续 AI
很难快速判断哪个文件是当前事实；如果直接把整个目录同步到官网，也会一并公开源码边界和
实现思路。

项目当前首先要保证后续开发和 AI 接手的连续性，其次才是用户文档与发布便利。

## 决定

1. 内部文档保留完整信息，作为项目维护的权威资料，不为了公开发布而删减。
2. `docs/public/` 是唯一可直接发布的文档白名单。
3. `docs/archive/` 只保存历史，不作为当前事实。
4. 根 `AGENTS.md` 和 `docs/README.md` 提供稳定入口，让后续 AI 不依赖历史对话。
5. 架构、发布边界和长期维护方式的决定写入 `docs/internal/decisions/`。
6. 公开文档只描述已实现、用户可以依赖的行为；内部实现说明不从公开文档反向恢复。

## 后果

- 官网、Git 静态页或发布脚本只需要复制 `docs/public/`。
- API 行为变化需要同时维护内部契约和公开函数页，但二者职责不同，不机械复制。
- 内部资料可以比公开文档更详细；两者冲突时必须用源码和测试核实并一起修正。
- 新任务只需从统一入口按需阅读相关资料，不必重新通读全部仓库或补交历史聊天记录。
