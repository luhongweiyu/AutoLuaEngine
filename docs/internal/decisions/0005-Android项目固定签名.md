# 0005：Android 项目固定签名

- 状态：已接受
- 日期：2026-07-29

## 背景

Android Gradle 在未声明签名配置时会使用构建机自己的默认 `debug.keystore`。该文件由
用户目录自动生成，不同电脑通常不同。相同包名但证书不同的 APK 无法覆盖安装，开发数据
迁移和跨机验证都会被迫卸载应用。

## 决定

1. `debug` 与 `release` 均使用 `engines/android/signing/xiaoyv-project.keystore` 中的同一把
   项目固定签名，别名为 `xiaoyv`。
2. 密码和相对路径写入 `engines/android/signing.properties`；keystore 与该属性文件作为当前
   多人联合开发阶段的项目资产，随 Git 同步。
3. Gradle 在签名配置缺失时必须失败，禁止无提示回退到构建机默认 debug 签名。
4. 新构建机正常拉取项目即可使用同一把签名；只拥有旧 APK 或证书指纹不能恢复私钥。

## 后果

- 从旧的默认 debug 签名迁移到固定签名需要一次卸载重装；之后两台电脑构建的 APK 可以
  相互覆盖安装。
- 这把签名是当前联合开发基线，不等同最终正式发布签名；发布策略统一时应以新的决策明确
  迁移方式，不能临时更换当前签名。
- Git 历史会包含当前签名材料，因此将来若改为公开源码或独立发布签名，必须先完成签名与
  发布边界的统一处理。
