# 0003：Android 脚本 API 兼容性设计基线

- 状态：已接受
- 日期：2026-07-27

## 背景

小鱼精灵后续会持续增加 Android 自动化能力。脚本用户通常已经熟悉懒人精灵和触动精灵的
函数写法；如果小鱼精灵为相同能力自行发明名称、参数或返回结构，会增加迁移和学习成本，
也会让 Lua 脚本生态出现不必要的差异。

## 决定

1. 新增 Android 脚本能力时，先核对当前源码、内部契约和公开的懒人精灵、触动精灵文档。
2. 对两者一致或可直接兼容的能力，函数名称、参数顺序、可选参数、默认值、返回值和失败
   语义默认沿用其文档约定。
3. Lua 绑定尤其遵守这条基线；核心实现与 C ABI 可以为稳定性做内部适配，但不能迫使 Lua
   用户接受无必要的新接口形状。
4. 如果两份参考文档存在实质差异，由实现者结合兼容性、清晰度和长期稳定性自行选择更优
   的一方；只有认为两者之外存在明显更优的名称、参数或返回结构时，才先列出对比和理由
   向用户确认。
5. 参考文档只用于接口设计核对，不复制大段外部文档内容。最终确定的真实行为仍写入本项目
   的内部 API 契约和公开脚本文档。

## 后果

- 新功能设计时多一道兼容性核对，但用户迁移现有 Lua 脚本的成本更低。
- 后续 AI 不需要依赖历史聊天记录；它必须在设计 Android API 前执行这项核对。
- 已经发布的项目 API 仍以本项目契约、源码和测试为事实依据，外部文档不会覆盖现有实现。
