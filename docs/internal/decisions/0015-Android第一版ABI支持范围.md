# 0015：Android 第一版 ABI 支持范围

- 状态：已接受
- 日期：2026-08-03
- 更新：[0008：Android Lua CFFI 上游接入](<0008-Android Lua CFFI上游接入.md>)中的发布与验收范围

## 背景

0008 为 cffi-lua 与 libffi 保留了 Android 四种 ABI 的上游实现，并据此要求四种 ABI 都完成
运行时探针。当前 Android 工程实际只提供 `arm64-v8a` 和 `x86_64` 两个 product flavor，第一版
也不计划发布 32 位 APK。上游源码可支持的架构与产品承诺的架构需要分开记录。

## 决定

1. 第一版 APK、插件 SO、FFI 外部库和可选 native 扩展只支持 `arm64-v8a` 与 `x86_64`。
2. `armeabi-v7a` 与 `x86` 不进入第一版构建、发布、兼容承诺或运行时验收范围。第三方源码中
   可继续保留对应上游实现，保留源码不代表产品支持。
3. 当前构建、测试、导入说明和发布检查均以这两种 64 位 ABI 为准。外部 SO 必须与设备所装
   APK 的 ABI 一致；导入成功不代表 linker 一定能够加载不匹配或缺少依赖的文件。
4. 后续若增加 ABI，必须新增决策并同时补齐 APK flavor、全部 native 依赖与可选运行时、Worker
   启动链、FFI 回调和真实设备或模拟器验收，不能只打开一个 Gradle `abiFilter`。

## 后果

- 0008 关于 cffi-lua、libffi 版本、静态编入方式和公开入口的决定继续有效。
- 0008 第 3 项所列四种 ABI 及“升级时验证四种 ABI”的要求，不再代表当前发布边界；第一版只对
  `arm64-v8a` 和 `x86_64` 承诺构建与验收。
- 32 位相关上游源码可以为未来扩展保留，但不应出现在当前能力说明、发布清单或完成度判断中。
