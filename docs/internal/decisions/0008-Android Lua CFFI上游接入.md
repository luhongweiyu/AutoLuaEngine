# 0008：Android Lua CFFI 上游接入

- 状态：已接受
- 日期：2026-07-29
- 更新：[0015：Android 第一版 ABI 支持范围](0015-Android第一版ABI支持范围.md)将当前发布与
  验收范围限定为 `arm64-v8a`、`x86_64`；本记录中的四 ABI 仅表示上游源码能力。

## 背景

原有 Android Lua `ffi` 是一段手写的动态库调用桥，只能解析少量整数、指针和 `char*` 函数
原型。它不具备结构体、数组、浮点、回调或可变参数的通用 C ABI 能力，继续逐项补写会把 ABI
规则、生命周期和每个 CPU 架构的差异散落在项目代码中，难以验证和升级。

项目已经明确需要让脚本扩展开发能够使用 C ABI，但该能力不应反向限制 `m` 的正式脚本 API
命名或内部 `_host` 的实现方式。

## 决定

1. 将 `q66/cffi-lua` 固定为 `v0.2.4`（提交 `1d6d54b4068eefc6dc4c4455175b6d0e530fa72a`），
   并配套固定 `libffi v3.7.1`（提交 `5c1c43091ed611fdea774374355eb938c73a9157`）。两者均以
   静态源码方式编入 `libengine.so`；源码目录中的 `UPSTREAM.md`、原许可证和归档哈希共同定义
   升级来源。
2. 保持脚本公开入口不变：`m.ffi`、默认全局 `ffi` 与 `require("ffi")` 指向同一个模块表。
   `cffi` 仅是上游静态模块入口符号，不新增 `require("cffi")` 作为公开承诺，也不在本轮更新
   `lr` 或 `cd` 兼容命名空间。
3. Android 的 `arm64-v8a`、`armeabi-v7a`、`x86` 和 `x86_64` 都使用对应上游 libffi 汇编实现；
   回调使用静态 trampoline，不要求运行时下载、生成可执行文件或引入 Autotools。
4. C ABI 入口在真实设备/模拟器探针稳定通过前维持“实验性”状态。用户文档说明可用
   范围、内存和线程边界，但不把 FFI 误写成安全的 Android 系统接口替代品。

## 后果

- 脚本可声明和使用更完整的 C 类型与调用规则；ABI 细节由上游维护的实现集中处理，而非项目
  自行复制调用约定。
- APK 原生代码体积增加，并新增两个需持续关注许可证、安全公告和上游升级的第三方依赖。
- 错误的声明、指针、库路径或回调线程仍可能导致原生崩溃；正式设备能力应优先经 `m` 和平台
  桥接层开放。FFI 适合受控的扩展开发，不替代公开 API 的兼容性设计。
- 升级时必须重新核对上游源码哈希、许可证和项目实际启用 ABI 的汇编源文件，并至少在一种正式
  支持的 ABI 上运行真实探针；不能只替换单个头文件或只在宿主机上编译。
