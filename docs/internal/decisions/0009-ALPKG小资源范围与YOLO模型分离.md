# 0009：ALPKG 小资源范围与 YOLO 模型分离

- 状态：已接受
- 日期：2026-07-30

## 背景

ALPKG 是脚本项目的加密分发容器，运行时从包内读取 Lua 和普通资源，不解压为 native 库目录。
YOLO 模型的参数、权重和相关文件通常远大于脚本资源，若把它们纳入 ALPKG，就会把模型路径、
临时落盘、缓存和清理策略与脚本包机制耦合，也不能解决 Android native 库装载问题。

## 决定

1. ALPKG 的定位是 Lua 脚本及小型静态资源，不作为大型推理模型或 native 运行时的分发容器。
   当前不以一个未验证的统一字节阈值定义“小型”，后续如需限制大小，应另行制定并实现可见的
   打包校验。
2. YOLO 的 `param`、`bin`、标签及其他模型运行所需资源只接受普通文件系统路径；不支持从
   ALPKG 读取，也不为此引入自动解包、临时复制或任务结束清理。

## 后果

- YOLO 的未来 Lua API 需要明确接收外部路径，模型由脚本作者或应用安装流程单独部署和更新。
- 打包器和用户文档不得把 YOLO 模型列为可随 ALPKG 一起分发的资源；若未来确有大模型分发需求，
  应设计独立的模型包、校验和生命周期，而不是扩张 ALPKG 的职责。
- 这项决定不预设 YOLO 的公开函数形状、是否提供兼容入口，或可选 native runtime 的具体装配方式。
